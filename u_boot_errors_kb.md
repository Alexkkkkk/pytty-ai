# База знаний: ошибки U-Boot при прошивке через USB (M7332, Amlogic, TV-приставки)

## Главная диагностика USB-флешки (делать ВСЕГДА в первую очередь)

1. `usb stop` затем `usb start` — переинициализировать USB.
2. `usb tree` — увидеть, определилась ли флешка (должно быть "N storage device(s) found").
3. `usb part` — таблица разделов. Должен быть раздел 0:1 с типом FAT.
4. `fatls usb 0:1 /` — СПИСОК ФАЙЛОВ в корне. Если файл прошивки виден — флешка ОК.
5. Если флешка не читается — почти всегда виновата файловая система/разметка (см. ниже).

## ОШИБКА: "partition N not valid on device 0" + "unable to use usb 0:N for fatload"

Причина: U-Boot не видит FAT-раздел на флешке. Типичные причины:
- флешка отформатирована в NTFS или exFAT (U-Boot читает только FAT16/FAT32);
- разметка GPT вместо MBR;
- флешка слишком большая (64–128 ГБ) с exFAT по умолчанию.

Исправление:
- Переформатировать флешку: схема разделов **MBR**, файловая система **FAT32**, один первичный раздел.
- Windows: Rufus (схема MBR + FAT32) или diskpart:
  `diskpart` → `list disk` → `select disk N` → `clean` →
  `create partition primary` → `select partition 1` →
  `format fs=fat32 quick` → `assign`
- Лучше флешка 4–32 ГБ, воткнута напрямую, без хабов.

## ОШИБКА: "unable to read ... from usb 0:1" / "reading upgrade_image.pkg" без результата

Причина: файл не найден или раздел не читается.
- Проверить `fatls usb 0:1 /` — файл должен лежать В КОРНЕ, имя ровно как ожидает загрузчик (например upgrade_image.pkg, MstarUpgrade.bin — регистр и расширение важны).
- Если не виден — вернуться к разделу про FAT32/MBR выше.

## ОШИБКА: "Bad signature on 0:1: expected 0x5840, got 0x0000"

Причина: загрузчик прочитал вместо сигнатуры пакета нули/мусор. Значения:
- флешка не читается (чаще всего — сначала исправить FAT32/MBR и проверить fatls);
- файл прошивки битый (битая закачка) или НЕ от этой платы;
- файл в корне не тот (например лежит в подпапке, нулевого размера).

Исправление:
1. Убедиться, что `fatls usb 0:1 /` показывает файл с НЕНУЛЕВЫМ размером.
2. Перекачать пакет заново, сверить размер с источником, желательно сверить MD5/SHA.
3. Пакет должен быть именно для этой модели/платы (M7332 и т.п.) — от другой платы даст Bad signature или AVB-ошибки.

## ОШИБКА: "No boot device" (при usbboot)

Это НЕ ошибка прошивки. Команда `usbboot` грузит ОС с USB-носителя (как с HDD).
Для прошивки использовать НЕ usbboot, а:
- `usb_super_upgrade_to_emmc` — полная прошивка eMMC с USB;
- `usb_partial_upgrade_to_emmc` / `ustar` — частичная прошивка (kernel + rootfs);
- `bin2emmc` — залить .bin-образ на eMMC.

## ОШИБКИ AVB при загрузке: "avb_ops_uboot.c: write/read offset is out of partition size", "Error validating A/B metadata from disk. Resetting and writing new A/B"

Причина: eMMC повреждена, разметка GPT разрушена или прошит неверный/чужой образ. Устройство не может проверить подпись boot-раздела и падает в консоль (видно "jump_to_console start!!").

Исправление:
1. Не паниковать — консоль U-Boot доступна, устройство восстановимо через USB.
2. Подготовить флешку (FAT32/MBR) + правильный пакет (см. выше).
3. Запустить полную прошивку: `usb_super_upgrade_to_emmc`, дождаться 100%, затем `reset`.
4. Если прошивка не стартует из-за проверки подписи — иногда помогает
   `avbab disable-verity` (отключить dm-verity) перед загрузкой, но лучше шить корректный пакет.
5. Проверить состояние слотов: `avbab dump`.

## Полезные команды U-Boot (шпаргалка)

- `help` — список всех команд.
- `usb start | usb stop | usb tree | usb part | usb storage | usb info` — USB.
- `fatls usb 0:1 /` — файлы в корне флешки; `fatinfo usb 0:1` — инфо о разделе.
- `fatload usb 0:1 0x10000000 file.bin` — загрузить файл в память по адресу.
- `mmc list`, `mmc info` — информация о eMMC.
- `gpt read mmc 0` — прочитать GPT eMMC (видно разделы).
- `printenv` / `setenv имя значение` / `saveenv` — переменные окружения.
- `bdinfo`, `showboard`, `version` — информация о плате.
- `reset` — перезагрузка.

## Стандартный протокол восстановления (по шагам)

1. Флешка ≤32 ГБ → MBR + FAT32 → в корень правильный upgrade_image.pkg.
2. В консоли U-Boot:
   `usb stop` → `usb start` → `usb part` → `fatls usb 0:1 /`
   (файл должен быть виден; если нет — другая флешка/порт)
3. `usb_super_upgrade_to_emmc` — ждать завершения (НЕ выключать питание!).
4. `reset` — устройство должно загрузиться.
5. Если Bad signature — перекачать пакет, проверить, что он для этой модели.

## Типичные ловушки

- Прошивка "зависает" на записи — НЕ выключать питание, дождаться конца.
- Флешка определилась в `usb tree`, но `fatls` пуст → NTFS/exFAT/GPT, переформатировать.
- После прошивки циклический ребут — прошит чужой/битый образ, шить заново правильный.
- "WDT is not Enable" — информационное сообщение, не ошибка.

# РАЗДЕЛ 2. Платформы: типовые программные ошибки и решения

## 2.0. Общие аппаратно-программные проблемы (все платформы)

| Симптом | Причина | Решение |
|---|---|---|
| Зависание на логотипе, bootloop | износ/повреждение eMMC (китайские MLC/TLC изнашиваются за 2–4 года) | замена eMMC (BGA153, программатор RT809H/T56) + заливка дампа |
| Устройство не стартует, чёрный экран после прошивки | убит SPI-флеш загрузчика | выпаять SPI (SOP8), прошить на CH341A + переходник, или заменить |
| "Смарт система заблокирована" (China TV) | сбой/блокировка Smart-системы | вход в factory menu (Info+Menu+Mute+Power или Source+2+5+8+0), сброс, перепрошивка через USB |
| Нет реакции на пульт, вечная загрузка | повреждён boot/env раздел | прошивка полного дампа через USB/программатор |
| Где брать прошивки | — | форумы: kenotrontv.ru (раздел Files), 4pda.to, специализированные форумы; брать ТОЛЬКО под свою модель и panel_id |

Инструменты: программаторы CH341A (SPI/NOR), RT809H / T56 (eMMC, NAND), Amlogic USB Burning Tool, RKDevTool (Rockchip), HiTool (HiSilicon), MStar ISP Tool.

## 2.1. MStar / SigmaStar (M7332, MSD6A648, MSD6A638, MSO9280, MSO9385...)

Типовые ошибки и решения:
- `Bad signature on 0:1: expected 0x5840` → флешка не FAT32/MBR или битый upgrade_image.pkg (см. Раздел 1).
- Bootloop с AVB-ошибками (`avb_ops_uboot`, `Error validating A/B metadata`) → eMMC повреждена: полная прошивка `usb_super_upgrade_to_emmc`, при износе eMMC — замена + дамп.
- Восстановление дампов SPI: прошить SPI-флеш исправным дампом под конкретную платформу (MStar/SunPlus дампы распространяются на форумах, напр. kenotrontv).
- Factory menu обновление: файл `MstarUpgrade.bin` (или upgrade_image.pkg) в корень FAT32-флешки → вход в MStar Upgrade mode при включении.
- Ошибка `project_id.ini` не найден/не совпадает → в папке прошивки должен быть корректный project_id.ini; без него установщик отказывается шить.

## 2.2. Amlogic (S905X, S905X2/X3, S905W, S912, S922X — TV box)

Прошивка: **Amlogic USB Burning Tool** (Windows), устройство в recovery/maskrom:
- зажать кнопку Reset (скрепкой в AV-отверстии) → подключить USB к ПК → отпустить.
- Или в U-Boot: `run update` / `aml_burn` если консоль доступна.

Типовые ошибки:
- Burning Tool зависает на 2–7% → битый образ .img, плохой кабель/USB-порт, драйверы; попробовать другой образ/кабель, порт USB 2.0.
- "Parse burning message failed" → образ не для этой модели (проверить dtb/плату).
- Bootloop после прошивки → неверный dtb для платы (для S905X3/S905W образы несовместимы!), шить правильный образ.
- Box не определяется в Burning Tool → проверить микросхему USB-хаба/связку, питание, зажать reset ДО подключения питания USB.

## 2.3. Realtek (RTD2982, RTD2995, RTD2871 — Philips/TCL/Toshiba Smart TV)

Прошивка: файл `install.img` в корень FAT32-флешки → воткнуть → включить ТВ (иногда с зажатой кнопкой на корпусе). Или через U-Boot: `uart_wipe` / update по сценарию вендора.

Типовые ошибки:
- Зависание на логотипе, не запускается Smart → прошить install.img, при износе eMMC — замена.
- ТВ не видит флешку → только MBR+FAT32, файл строго install.img в корне.

## 2.4. Novatek (NT72563, NT72671, NT72676 — LED TV)

Прошивка: `upgrade_loader` / V8-…pkg на FAT32-флешке, запуск из service menu (Source → 2 5 8 0 на пульте) или автообновление при включении.

Типовые ошибки: bootloop, кирпич после обрыва прошивки → та же процедура с корректным файлом под плату (номер платы на шелкографии!).

## 2.5. HiSilicon (Hi3716MV430, Hi3798MV100/200 — приставки операторов, ТВ)

Прошивка: **HiTool** (HisiLoader) по USB (fastboot-режим: зажать кнопку при подключении USB) — заливаются fastboot-образы (boot/system) или полный набор .img.

Типовые ошибки:
- HiTool не видит устройство → драйверы, режим fastboot, кабель.
- Загрузка до логотипа и стоп → шить полный комплект (fastboot + приложение), проверять разметку.

## 2.6. Rockchip (RK3228, RK3229, RK3328, RK3399 — дешёвые TV box)

Прошивка: **RKDevTool / SocToolKit** (AndroidTool), режимы:
- Loader mode (зажать кнопку при включении) — если загрузчик жив.
- Maskrom (замкнуть CLK eMMC или кнопку) — если загрузчик убит.

Типовые ошибки:
- "Download boot fail" → битый образ, плохой контакт maskrom.
- Box в maskrom не входит → замыкание пинов NAND/eMMC (отпайка дорожки CLK) — работа программатором.
- Неверный образ → вечная перезагрузка; шить update.img именно этой модели.

## 2.7. SunPlus / GX (GX6605S, GX6102S — спутниковые ресиверы)

Прошивка: дамп SPI-флеш (SOP8) на программаторе CH341A; файл .bin под конкретную плату. В U-Boot часто есть `gxusb` / обновление с флешки, но после неудачной прошивки — только программатор.

Типовые ошибки: чёрный экран, нет отклика — прошить SPI дампом (форумы kenotrontv/gsmserver), проверить питание флеш (3.3 В).

## 2.8. MediaTek (MT5596, MT5597, MT5862, MT5658 — Sony/Philips/Panasonic TV)

Прошивка: signed-пакеты через USB-автообновление (файлы `autorun` / upgrade.pkg в корне FAT32) или через сервисный режим. Консоль U-Boot: команды `ustar`, `usb_super_upgrade_to_emmc` (см. Раздел 1).

Типовые ошибки:
- AVB Bad signature, откат в консоль → eMMC/пакет; решения в Разделе 1.
- ТВ не принимает пакет → пакет не подписан под эту модель/регион.

## 2.9. Правила, общие для всех платформ

1. Прошивать ТОЛЬКО файл под свою модель/плату (номер платы = шелкография, panel_id = наклейка матрицы).
2. Флешка: MBR + FAT32, один раздел, файл в корне, короткое имя.
3. Во время прошивки не выключать питание.
4. При подозрении на износ eMMC (bootloop после правильной прошивки) — диагностика заменой eMMC.
5. Перед прошивкой изымать сетевой кабель/отключать Wi-Fi (некоторые системы лочатся облачно).

## Вход в консоль и принудительное обновление ТВ (MStar/SigmaStar и другие)

- **Пробел при старте ТВ** — прерывает автозагрузку и открывает консоль U-Boot.
  Посылать сразу после включения питания, несколько раз подряд, пока не
  появится приглашение `>>#`.
- **Зажать Tab при старте** — принудительный вход в режим обновления с USB:
  устройство само ищет MstarUpgrade.bin / upgrade_image.pkg на флешке.
- На других платформах вместо Пробела могут работать: **Enter**, **Esc**,
  **x**, точка **.** — пробовать по очереди сразу после подачи питания.
- Тайминг критичен: клавишу посылать в первые 1–3 секунды после включения,
  до старта загрузки ядра. Если опоздали — выключить/включить и повторить.
- В PuTTY-AI есть кнопки быстрой отправки клавиш: Пробел, Tab, Enter, Esc,
  Ctrl+C (панель инструментов, работают при Serial-подключении).
# Раздел 3. Лучшие решения с профильных форумов

Источники: kenotrontv.ru, mslw.com/bb, remont-aud.net, televid-sib.org.
Каждое решение проверено практикой мастеров.

## 3.1 Smart-TV и блокировки

- **«Смарт система заблокирована», появляется после подключения Wi-Fi** —
  это ОБЛАЧНАЯ блокировка: перепрошивка по USB НЕ помогает, блокировка
  возвращается при выходе в сеть. Решение: вычитать eMMC программатором,
  из РОДНОГО дампа вытащить ключи (MAC, USID, ключи DRM) и внедрить в
  рабочий дамп перед записью; либо восстановить только нужные разделы.
  MAC-адрес есть на наклейке майны и в сервисном меню.
- **Сервисный порт в Smart-TV «закрыт»** — норма: для сервисных
  манипуляций через терминал порт закрыт прошивкой; работаем через
  программатор eMMC/SPI либо через USB-update mode.
- **Не гадать и не «проливать» USB-прошивки подряд** — сначала
  диагностика: лог чтения eMMC программатором (тест адресов), потом
  решение.

## 3.2 eMMC — главная болезнь Smart-TV

- Зависание на логотипе, вечная загрузка, bootloop после 2–4 лет —
  износ китайской eMMC. Диагностика: лог чтения программатора
  (RT809H/T56/UFPI) — ошибки на адресах = износ.
- Перед заменой eMMC: с родной ОБЯЗАТЕЛЬНО вычитать дамп — там ключи
  (MAC/USID/Wi-Fi/DRM), без них Smart не заработает как раньше.
- Замена: BGA153, литьё феном + шаблон. Новую eMMC шить адаптированным
  дампом (родные ключи + чужой рабочий образ).
- Решение «только разделы»: не обязательно перезаписывать всю eMMC —
  часто достаточно boot/env/dtb и раздела с ключами.

## 3.3 Платы TP.* (китайские шасси) — читаем шелкографию

- Плата вида **TP.MSxxxx.PBxxx** (MStar/SunPlus) — прошивка строго под
  плату + матрицу (panel_id!). Файл: MstarUpgrade.bin / upgrade.bin
  на FAT32-флешке → USB-обновление из сервис-меню или при старте.
- Нет прошивки под шасси — ищем на форумах по полному имени платы
  (напр. TP.MS3463S.PB801 + модель матрицы LC320DXJ).
- Вход в сервис-меню китайских ТВ: Source → 2 5 8 0; или Menu+2+5+8+0;
  на DEXP/TCL/Haier часто Info+Menu+Mute+Power.

## 3.4 SPI Flash (8-ногая) — быстрое восстановление

- Убитый SPI (чёрный экран, нет старта) — выпаять 25Q64/25Q128,
  прошить CH341A + переходник SOP8 (зажим — без выпаивания!).
- Дампы SPI под платформы MStar/SunPlus распространяют на форумах
  (раздел SPI REPAIR на kenotrontv) — шить дамп под СВОЮ ревизию платы.

## 3.5 Подсветка и матрицы (самый частый ремонт)

- ТВ «звук есть, изображения нет» — фонариком по экрану: видно
  изображение = подсветка. Меняем LED-линейки целиком (все полосы),
  не по одному диоду — остальные скоро сдохнут.
- Перед сборкой: проверить драйвер подсветки (напряжение, ток) —
  иначе новые линейки тоже перегорят.
- Матрица с разбитыми шлейфами TAB — ремонт на паяльной станции
  (COF/TAB bonding) или замена матрицы; «разводы/полосы» при надавливании
  на шлейф = контакт TAB — иногда лечится прогревом.

## 3.6 Питание

- ТВ не стартует, нет дежурки — проверить предохранитель, затем
  ключевой транзистор, диодную сборку, ШИМ. Лампочка дежурки мигает —
  чаще всего подсветка/БП в защите.
- Вздутые электролиты в БП — менять все в силовой цепи, не только вздутые.

## 3.7 Прошивка через USB по платформам (шпаргалка)

- **MStar/SigmaStar**: MstarUpgrade.bin в корень FAT32 → воткнуть →
  включение; консоль U-Boot: Пробел при старте, usb start, fatls,
  ustar / usb_super_upgrade_to_emmc.
- **Amlogic**: USB Burning Tool + кнопка Reset; зависание на 7% = битый
  образ/кабель.
- **Realtek**: install.img в корень FAT32.
- **Rockchip**: RKDevTool, maskrom/loader.
- **Призрачный брак**: флешка USB 3.0 не читается загрузчиком —
  брать USB 2.0 4–16 ГБ, FAT32, MBR.

## 3.8 Правила мастеров (копилка форумов)

1. Сначала диагностика, потом прошивка — «не гадать».
2. Родной дамп вычитывать ДО экспериментов — всегда.
3. Прошивать только под свою плату/матрицу.
4. Ключи (MAC/USID) — святые: терять нельзя.
5. После ремонта — тест 2–4 часа под нагрузкой.
6. Разъёмы шлейфов матрицы — крайне хрупкие, без фанатизма.

# Раздел 4. Ремонт через терминал и консоль (с форумов kenotrontv/mslw/televid-sib)

## 4.1 Восстановление SPI-дампов (KenotronTV SPI REPAIR)

- Существует специализированная программа **KenotronTV SPI Repair** —
  анализ и восстановление дампов SPI Flash платформ MStar/SunPlus:
  разбор структуры, проверка CRC, поиск повреждённых областей,
  формирование восстановленного бинарника.
- Если дамп убит и донора нет — нужен рабочий дамп такого же или
  совместимого шасси, либо recovery-пакет (USB-прошивка).
- Несколько повторных чтений (2–3) одной SPI Flash обязательны —
  сравниваем чтения, несовпадения = битые области.
- Не редактируй неисправный дамп перед анализом — присылай как есть.
- В дампе есть ИНДИВИДУАЛЬНЫЕ области (ключи, калибровки) — их нельзя
  бездумно заменять донорскими данными.

## 4.2 Типичные терминальные сценарии восстановления

### MStar/SigmaStar (консоль U-Boot через UART):
```
(при включении жать Пробел до появления <<...>>#)
usb stop; usb start          # переинициализация USB
fatls usb 0:1 /              # файл виден? (FAT32/MBR!)
fatload usb 0:1 0x10000000 MstarUpgrade.bin
ustar                        # частичное обновление
usb_super_upgrade_to_emmc    # полная прошивка eMMC
saveenv; reset
```

### Прошивка только env (быстро, безопасно):
```
setenv bootcmd '...'         # правим переменные
saveenv; reset
```

### SunPlus:
```
spi read / update через меню загрузчика; дамп SPI читается
через программатор, терминал — для диагностики лога.
```

## 4.3 Железные проблемы, маскирующиеся под прошивку

- **25Q64 читается, но не стирается и не пишется** (защита не
  снимается, микросхему меняли) → проблема НЕ в прошивке: SPI-линии
  или процессор. Ищите обрыв дорожек, прозвоните линии CLK/DI/DO/CS.
- Прошивки с ДРУГОЙ панелью не идут — сначала добейтесь запуска
  «майна» (основной платы), потом ищите прошивку под свою матрицу.
- С любой прошивкой от этого шасси плата запустится, если исправен
  процессор. Не запускается ни с одной → железо, не софт.

## 4.4 Диагностика через консоль (что смотреть в логе)

- Лог загрузки до момента зависания — последняя строка укажет этап:
  DDR init → SPI/eMMC → ядро → инициализация панели.
- Зависло на DDR — память/процессор (железо).
- Зависло после `Starting kernel` — ядро/DTB/панель (софт или panel_id).
- Нет вывода вообще — проверить UART (RX/TX перепутаны? скорость
  115200? земля?), затем SPI-загрузчик.
- `Bad signature` / AVB-ошибки → см. Раздел 1 (прошивка с USB).

## 4.5 Правило форумов

«Сначала пусть майн запустится, потом ищи прошивку под матрас» —
последовательность: железо → загрузчик → основная прошивка → panel.

# Раздел 5. Вход в рекавери/сервис-режимы и смена матрицы

## 5.1 Рекавери и сервис-режимы по брендам

### Универсальные способы (Android TV):
- **Через ADB:** `adb reboot recovery` (USB-отладка должна быть включена;
  если нет — попробовать `adb reboot recovery` с выключенного через
  комбинацию кнопок).
- **Кнопки на корпусе:** зажать Vol+ (или Input/Source) на ТВ →
  включить питание → держать до появления логотипа/рекавери.
- **Скрепка в отверстие Reset:** зажать → включить → держать 10–15 сек.

### MStar/SigmaStar (шасси MSD/MSO, TP.MS*):
- USB-апдейт с флешки (MstarUpgrade.bin в корне FAT32) — при включении
  сам предложит обновление, либо из сервис-меню.
- Сервис-меню: Source → 2 5 8 0; на части шасси Menu+2+5+8+0.
- Консоль UART: Пробел при старте → `ustar` (recovery-обновление).

### Philips (Q... шасси):
- Комбинации: 0 6 2 5 9 6 + i+ (инфо) — или Source+2+5+8+0 в зависимости
  от шасси; точный код искать под модель.

### Hisense:
- Source → 2 5 8 0; Menu → 0 4 2 3 (зависит от шасси).

### TCL / Thomson / DEXP / BBK / Erisson (китайские шасси):
- Source → 2 5 8 0 — рабочий код почти для всех китайских шасси.
- Если не вошло — пробовать Info+Menu+Mute+Power с пульта.

### Если ничего не работает:
- UART-консоль (наш терминал!): перехват загрузки Пробелом →
  `usb_super_upgrade_to_emmc` — это и есть recovery через терминал.
- См. Раздел 1 (U-Boot) и Раздел 4 (терминальный ремонт).

## 5.2 Смена матрицы (панели)

### Подбор совместимой матрицы:
1. **Смотрим шлейф матрицы:** 30-pin или 51-pin LVDS, какое напряжение
   подсветки (смотреть шильдик блока питания/инвертора).
2. **По шильдику матрицы** (на обороте, напр. LC320DXJ-SFA1, T420HVN06)
   ищем совместимую с тем же разрешением и типом подсветки.
3. **Ресурсы:** разделы «Спецификации LCD LED панелей» (televid-sib),
   базы совместимости матриц на форумах.

### После замены матрицы — СОФТ:
- **Другая матрица = другая прошивка main-платы!** Панель определяется
  по panel_id; с новой матрицей нужна прошивка именно под неё
  (иначе изображения нет/артефакты).
- На китайских шасси TP.* — прошивка строго «плата + панель»:
  ищем по «TP.MSxxxx.PBxxx + имя матрицы».
- Иногда panel_id правится в сервис-меню (раздел Panel/Display), если
  матрица совместима по железу.

### Железо при замене:
- Шлейфы матрицы крайне хрупкие — без перегибов, защёлки аккуратно.
- T-con (плата на матрице): проверить конденсаторы, при греве одной
  зоны T-con — прогреть/заменить.
- Пересадка T-con со старой матрицы возможна только при 100%
  совместимости (той же панели).

## 5.3 Быстрый алгоритм «ТВ после замены матрицы не показывает»

1. Шлейфы вставлены до щелчка, не перегнуты?
2. Прошивка под НОВУЮ панель залита?
3. panel_id в сервис-меню соответствует?
4. Подсветка стартует? (ток, напряжение на LED-разъёме)
5. Изображение фонариком есть? → тогда панель/шлейф; нет — main.

# Раздел 6. Полная шпаргалка консольных команд (UART/terminal)

## 6.1 U-Boot: базовые команды (все платформы)

```
help                     список всех команд

```
**Перехват консоли:** сразу после включения жать Пробел / Esc / Enter
(зависит от платформы), пока не появится `>>#`.

## 6.2 U-Boot: память и файлы

```
mmc list                 список eMMC/SD
mmc info                 инфо о текущей eMMC

mmc read  addr blk cnt   читать блоки в память
mmc write addr blk cnt   писать блоки из памяти
fatls usb 0:1 /          список файлов на USB
fatload usb 0:1 0x10000000 file.bin   загрузить файл в RAM
fatwrite usb 0:1 0x10000000 file.bin size  записать на USB
sf probe 0               подключить SPI-флеш
sf read addr offset size  читать SPI
sf write addr offset size писать SPI
sf erase offset size     стереть SPI (ОПАСНО!)
nand info / nand erase.chip  NAND (ОПАСНО!)
mw.l addr value count    записать 32-битные слова в RAM
md.l addr count          вывести память (дамп)
cmp.b addr1 addr2 len    сравнить области памяти
```
